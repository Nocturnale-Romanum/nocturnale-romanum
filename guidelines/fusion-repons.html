Fusion des répons : guidelines

Nocturnale Romanum, dossier gabc/. Version de travail du 29/10/2026, tirée de l'étude de 5 répons déjà fusionnés par marteo.
Les points marqués « Question » attendent la confirmation de marteo.

1. Objet et périmètre

Pour chaque répons qui a plusieurs propositions, il faut produire une version fusionnée. Marteo (Matthias Bry) arbitre l'opération. Ce document décrit la façon dont marteo a fusionné jusqu'ici les propositions de dcrochu dans sa propre version _marteo, pour pouvoir appliquer les mêmes critères aux répons restants.

212 répons sont déjà fusionnés. Cette première version en étudie 5, choisis parce que les messages de commit expliquent les choix et couvrent des cas différents :

3. Méthode de lecture d'une fusion

Pour chaque pièce, on compare trois états du fichier :

  • P : _marteo juste avant le commit de fusion (git show M^:gabc/ID_marteo.gabc) ;
  • D : _dcrochu tel qu'il était à ce moment-là (git show M:gabc/ID_dcrochu.gabc) ;
  • N : _marteo après la fusion (git show M:gabc/ID_marteo.gabc).

Les syllabes sont alignées sur le texte. Pour chaque divergence entre P et D, on regarde N : la modification est adoptée si N = D, refusée si N = P, et retouchée si marteo a fait une troisième solution.

4. Règles observées

R1. Base et signes rythmiques. La fusion se fait dans _marteo. Ses signes rythmiques (épisème horizontal _, points de mora ./.., ictus ') sont toujours conservés, puisque dcrochu n'en met pas.
Corollaire : quand un changement de neume est adopté, marteo réajuste les signes rythmiques pour qu'ils correspondent au nouveau neume.

Deux coupes de dcrochu n'avaient pas été reprises : « contem/ptórem » (1122N3R1) et « san/ctum » dans le verset de 1122N3R2. Ce sont des oublis : il faut écrire « contemp/tórem » et « sanc/tum ». Ces deux pièces sont donc à reprendre.
R3. Mélodie : adoptée, sauf si le changement éloigne de la source manuscrite. Les cas observés :
  • Adoptée : MUXNN1R1 « con » h/ijg/hg → h/ijh/hg.
  • Refusée quand marteo suit volontairement un témoin : 1122N3R1, où il conserve le début particulier de l'altera pars du verset (« ta » fe au lieu de f, « te » eh au lieu de h), alors que dcrochu proposait une « standardisation du V/ à la médiante ».
  • Refusée par principe dans 0829N1R3 : « adhere to the Paleo table as much as reasonable ». Les neumes liés au changement mélodique sont refusés avec lui (« tán » cltr gardé contre clto-1hgvihh ; « él » e@fog|sa gardé contre e/fg|scM2).
R3 bis. Altérations. (Confirmé par marteo.)
  • Bécarres (y, Y) proposés par dcrochu : toujours adoptés.
  • Bémols (x, X) proposés ou supprimés par dcrochu : ne jamais trancher seul, il faut demander confirmation à un humain. On en a un exemple dans PMEXN1R2 : « Backported dcrochu's changes except the last flat si ».
Le bécarre ajouté par dcrochu sur « DIxit » dans 1122N3R1 (gydf…) n'avait pas été repris : c'est un oubli, il faut l'adopter. 1122N3R1 est à reprendre.
R4. Liquescences : refusées si le manuscrit ne les porte pas. 0508N2R1 : la liquescence sur « ALleluia » (g>|obvi>) est refusée, « because it is not in the ms version of this All. ».
Question 3. 1122N3R1 « cón » : P avait cl>, dcrochu proposait vi>, et marteo a finalement écrit cl~ (liquescence diminutive). Sur quel critère ?
R5. NABC, nature du neume : adoptée quand la mélodie ne change pas. Quand dcrochu identifie autrement un neume sur des notes identiques, marteo reprend son choix : vi-su3 → vi-sut1su2 (tractulus dans les subpunctis), to → toS, vi/pe… → scM2… (1122N3R1 « á »). Il ajoute aussi les hauteurs relatives quand elles manquent : pr → prhj, ci- → ci-hj. Il corrige celles qui sont fausses : vihj → vihl (1122N3R2, « Qui », trois fois).
Question 4. Dans 0829N1R3, des ajouts de hauteur pourtant analogues ont été refusés (cl!pi gardé contre clhj!pihj, cltohh contre cltohg), de même que le déplacement lsc2 → lsc3. Est-ce l'effet du principe « Paleo table » propre à cette pièce, ou une règle générale sur le placement vertical ?
R6. Espacement NABC en début de syllabe : // devient / ou rien. Les // que dcrochu met en tête de neume sont presque toujours réduits :
  • à / : 0508N2R1 (« Cu », « ho », « præ », « o »), 1122N3R2 « á », 1122N3R1 « tum » ;
  • à rien : 1122N3R1 « Hó », « di » ; 0829N1R3 « li » ; MUXNN1R1 « tu ».
Les décalages vers la gauche (``` → ````, MUXNN1R1 « Qui ») sont en revanche repris.
Question 5. Quelle est la règle exacte : / quand le neume précédent est proche, et rien sinon ? Dans quel cas un // est-il légitime ? Dcrochu lui-même a commité « // --> / » sur 0908N1R2.
R7. Lettres significatives : position adoptée, sous réserve de vérification sur le manuscrit. MUXNN1R1 : lssm2 → lssm3, lss2 → lss3, ajout de lsi7 et lsi8, tous adoptés. Mais un second commit replace un lsi « against dcrochu, having checked again with the ms ». Le manuscrit tranche.
R8. Conventions typographiques de marteo : conservées.
  • L'astérisque est une syllabe vide à part : <sp>*</sp>() (dcrochu le colle à la syllabe suivante, ce qui est refusé, 0829N1R3).
  • Balises T.P. dans l'ordre <c><i>T.P.</i></c>.
  • Orientation explicite de l'oriscus (O → O1) : adoptée.
  • Le texte romain est conservé quand dcrochu suit le texte d'un manuscrit (0810N3R2 : « kept the Roman text »).

Le message d'une fusion

Une fusion fait deux commits : marteo edited ID: … sur ID_marteo.gabc, puis marteo selected marteo's proposal for ID. Le message du premier dit ce qui a été repris et, surtout, ce qui a été refusé et pourquoi :

  • Backported dcrochu's changes : tout est repris ;
  • Backported most of dcrochu's changes. : l'essentiel est repris ;
  • Backported dcrochu's syllabisation, … syllabisation and NABC tweaks, … syllabisation and placement : report limité à ces aspects ;
  • Backported dcrochu's changes except <quoi> because <raison> ;
  • Backported some of dcrochu's changes - but I kept <quoi>, as <raison> ;
  • quand marteo repart entièrement de la version dcrochu : dcrochu as of JJ/MM/AAAA + rsigns, suivi après « ; » des retouches propres (; changed two bars to reflect the structure of the text).

Les syllabes visées s'écrivent avec la syllabe concernée en capitales : ALleluia, inTENde, vestimentis tuIS. Les messages de marteo sont en anglais. Ceux de dcrochu sont en français, en liste à puces par nature de changement : • syllabisation : … • GABC : … • NABC : ….

6. Procédure proposée pour un répons à fusionner

  1. Lire les messages de commit de ID_dcrochu.gabc depuis la dernière modification de ID_marteo.gabc : ils listent les changements proposés.
  2. Aligner _marteo et _dcrochu syllabe par syllabe, en ignorant le second en-tête de dcrochu et les signes rythmiques.
  3. Classer chaque divergence (syllabation, mélodie, liquescence, nature du neume, hauteur NABC, espacement, lettres significatives, typographie), puis appliquer R1 à R8.
  4. Réajuster les signes rythmiques sur les neumes modifiés (R1).
  5. Rédiger le message selon les gabarits du § 5, en justifiant chaque refus.
  6. Faire valider par marteo avant toute sélection.

7. Questions ouvertes (récapitulatif)

  1. Les coupes « contem/ptórem » et « san/ctum » ont-elles été conservées délibérément ? Réponse : non, ce sont des oublis. On adopte toujours la syllabation de dcrochu, sauf pour « quó/ni/am » (R2).
  2. Pourquoi le bécarre de « DIxit » (1122N3R1) n'a-t-il pas été repris ? Réponse : c'est un oubli. Les bécarres sont toujours adoptés, les bémols sont soumis à un humain (R3 bis).
  3. Sur quel critère « cón » a-t-il été mis en cl~ (1122N3R1) ?
  4. Les hauteurs NABC et le lsc3 refusés dans 0829N1R3 relèvent-ils du principe « Paleo table » ou d'une règle générale ?
  5. Quelle est la règle d'espacement : //, / ou rien ?
  6. Pour les fusions à venir : fait-on la modification directement dans ID_marteo.gabc (commit au nom de qui ?), ou dans une proposition à part, que marteo reprend ensuite ?
